# Документация проекта

Документация фиксирует согласуемую архитектуру, а не статус реализации.
Исходный код на этом этапе отсутствует.

## Порядок чтения

1. [Границы продукта](product-scope.md) — назначение, обязательный результат и
   ограничения.
2. [Зафиксированная база Chromium](chromium-baseline.md) — точная версия,
   воспроизводимость и политика обновлений.
3. [Архитектура](architecture.md) — компоненты, зависимости и жизненный цикл
   профиля.
4. [Модель подмены](fingerprint-model.md) — поверхности наблюдения,
   согласованность и границы достижимого.
5. [Управление профилями](profile-management.md) — локальная админ-панель,
   хранение и безопасность.
6. [Сборка и выпуск](build-and-release.md) — путь к готовому дистрибутиву.
7. [Проверка](verification.md) — доказательства корректности и критерии
   готовности.
8. [Источники](references.md) — первичные материалы, на которых основаны
   решения.

## Полномочия документов

`product-scope.md` определяет продуктовые границы; `chromium-baseline.md` —
единственный владелец версии upstream; `fingerprint-model.md` — наблюдаемое
поведение профиля; `architecture.md` — размещение ответственности;
`verification.md` — требуемые доказательства. Детали реализации, не влияющие
на эти правила, выбираются при разработке и не закрепляются заранее.
